# Правила работы с репозиторием

## Основы проекта

- «Печатная плата» — статический сайт в стиле технического печатного журнала 1987 года.
- Тематика: микроэлектроника, домашние компьютеры, схемы, радиолюбительство и техническое творчество.
- Базовые технологии: HTML, CSS и необязательный JavaScript без этапа сборки.
- Целевая площадка публикации — GitHub Pages.
- Не добавлять фреймворк, систему сборки или новую зависимость без предварительного обсуждения. Если ручная поддержка страниц станет неудобной, сначала обсудить переход на генератор статических сайтов.

## Язык и документация

- Основной язык интерфейса, статей и документации — русский.
- README содержит краткое описание проекта, инструкции по локальному просмотру и публикации.
- `ROADMAP.md` отражает актуальные этапы развития проекта.
- При изменении структуры проекта, команд, процесса публикации или правил синхронно обновлять README и этот файл.

## Процесс разработки

- Ветка `main` должна оставаться работоспособной.
- Изменения вносить через отдельные ветки и небольшие pull request.
- Один pull request должен решать одну законченную логическую задачу.
- Не изменять оформление или структуру существующих страниц попутно с независимой задачей.
- Коммиты оформлять с префиксами `feat:`, `fix:`, `docs:`, `refactor:`, `style:` или `chore:` и кратким описанием результата.
- Не хранить в репозитории секреты, временные файлы, редакторские настройки и результаты локальной генерации.

## HTML, CSS и JavaScript

- Использовать семантическую разметку HTML и логичную иерархию заголовков.
- Основной контент и навигация должны быть доступны без JavaScript.
- JavaScript применять только для прогрессивного улучшения интерфейса.
- Стили и сценарии размещать в отдельных файлах; не использовать разрозненные inline-решения.
- Общие цвета, шрифты, отступы и другие параметры оформления задавать через CSS-переменные.
- Использовать адаптивную вёрстку: сначала обеспечивать удобство на узком экране, затем расширять композицию для широких экранов.
- Сохранять стиль технического журнала, но не жертвовать ради него читаемостью и доступностью.

## Контент и материалы

- Публиковать законченные материалы вместо большого количества заглушек.
- Использовать единый формат заголовков, подписей, схем, таблиц, источников и ссылок.
- Отделять исторические факты от художественной стилизации.
- Указывать источники исторических сведений и происхождение заимствованных материалов.
- Не добавлять изображения, сканы или тексты с неясными правами использования.
- Оптимизировать изображения перед добавлением и сохранять стабильные, человекочитаемые адреса страниц.

## Проверка изменений

Перед завершением изменения проверять результат в браузере, а не ограничиваться просмотром кода:

- открыть изменённые страницы и пройти по связанным с ними внутренним ссылкам;
- проверить узкий мобильный и широкий экран;
- проверить навигацию с клавиатуры и заметность фокуса;
- убедиться в достаточном контрасте и наличии текстовых альтернатив изображений;
- учитывать настройку `prefers-reduced-motion` при добавлении анимации;
- проверить отсутствие ошибок JavaScript, неработающих ссылок и лишних сетевых запросов;
- после настройки публикации дополнительно проверить опубликованную версию сайта.
