# План развития проекта

## Исходный подход

Сайт начинается как набор статических страниц на HTML и CSS с необязательным JavaScript и публикуется через GitHub Pages. Новые технологии и дополнительные возможности добавляются только при появлении практической необходимости.

## 1. Концепция

- [ ] Определить название и слоган журнала.
- [ ] Уточнить основные рубрики: микроэлектроника, домашние компьютеры, схемы, радиолюбительство и техническое творчество.
- [ ] Определить характер контента: исторические материалы, современные статьи в ретростиле или вымышленный журнал.
- [ ] Установить правила указания источников, авторства и происхождения изображений.

## 2. Структура сайта

- [ ] Создать главную страницу с выпусками и рубриками.
- [ ] Создать шаблон и первые отдельные страницы статей в `articles/`.
- [ ] Добавить страницы «О журнале», «Архив» и «404».
- [ ] Организовать ресурсы в `assets/css/`, `assets/js/` и `assets/images/`.
- [ ] Использовать стабильные и человекочитаемые URL.

## 3. Оформление

- [ ] Сформировать визуальный язык технического журнала 1987 года: бумага, типографская сетка, чертежи, схемы и рубрикация.
- [ ] Задать цвета, шрифты, отступы и параметры компонентов через CSS-переменные.
- [ ] Реализовать адаптивную вёрстку для мобильных и широких экранов.
- [ ] Обеспечить современную читаемость, навигацию с клавиатуры и доступность.

## 4. Первые материалы

- [ ] Подготовить 2–3 законченные статьи вместо большого количества заглушек.
- [ ] Применить единый формат заголовков, подписей, схем, таблиц и ссылок.
- [ ] Указать источники исторических фактов и происхождение заимствованных изображений.
- [ ] Проверить права использования материалов и оптимизировать изображения.

## 5. Проверка качества

- [ ] Проверить семантическую разметку HTML и иерархию заголовков.
- [ ] Проверить навигацию с клавиатуры, заметность фокуса и текстовые альтернативы изображений.
- [ ] Проверить контраст и поддержку `prefers-reduced-motion`.
- [ ] Проверить отображение на узком мобильном и широком экране.
- [ ] Убедиться в отсутствии неработающих ссылок, ошибок JavaScript и лишних запросов.

## 6. Публикация

- [ ] Настроить GitHub Pages.
- [ ] Добавить в README инструкции по локальному просмотру, структуре проекта и публикации.
- [ ] Проверить опубликованную версию: главную страницу, статьи, изображения и внутренние ссылки.

## Критерий первой публичной версии

Первая версия готова, когда на опубликованном сайте есть главная страница, 2–3 законченные статьи, страница «О журнале», работающая навигация и адаптивное оформление, а все основные страницы проверены в браузере.

## Дальнейшее развитие

Эти возможности рассматриваются после публикации первой версии:

- архив по выпускам и темам;
- RSS при регулярном появлении новых материалов;
- поиск после накопления достаточного количества статей;
- генератор статических страниц, если ручное поддержание HTML станет неудобным.
