# 0001. Фиксируем архитектурные решения

Статус: принято (2026-11-03)

## Контекст

Код показывает устройство проекта, но не объясняет причины решений и отклонённые альтернативы. Без этих сведений архитектурные ограничения легко нарушить при последующих изменениях.

## Решение

Каждое значимое решение записывается в `docs/adr/NNNN-short-name.md` на русском языке. При необходимости рядом добавляется английская версия `.en.md`.

Запись содержит номер, статус и дату, контекст, решение, реальные альтернативы и последствия. Принятые записи не переписываются: изменённое решение получает новый ADR, а старый ссылается на замену. Номера сквозные и не переиспользуются. ADR требуется для решений, которые дорого развернуть, но не для локальных деталей реализации.

## Альтернативы

- **Только комментарии в коде.** Подходят локальным причинам, но не сохраняют сквозную историю.
- **Одна страница архитектуры.** Быстро устаревает и теряет отклонённые альтернативы.
- **Не записывать решения.** Проще сразу, дороже при сопровождении.

## Последствия

- (+) Причины и компромиссы доступны людям и агентам.
- (+) Новые решения начинаются с понимания существующих ограничений.
- (−) Значимая работа требует дисциплинированной документации.
