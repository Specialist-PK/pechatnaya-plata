# 0011. Композиция страниц по оригинальному скану

Статус: изменено ADR-0012 (2026-11-04), заменяет ADR-0009

## Контекст

Универсальные двухколоночные страницы и отдельный разворот только для принципиальной схемы увеличили статью «Ваш помощник — компьютер» до семи страниц. В оригинале она занимает страницы 19–22: первая часть схемы делит страницу 20 с текстом и картой памяти, вторая занимает страницу 21, а финал содержит временную диаграмму и три текстовые колонки.

## Решение

Для исторических статей допускаются специализированные печатные сетки, воспроизводящие композицию источника. В статье «Специалист» используются четыре страницы: 19 — заставка, две колонки и структурная схема; 20–21 — разворот принципиальной схемы с текстовой колонкой и картой памяти; 22 — временная диаграмма, три колонки и технические характеристики.

Markdown title поддерживает компонуемые через пробел указания: `column` размещает иллюстрацию в колонке, `lead` обозначает ведущую иллюстрацию финальной трёхколоночной страницы, `page-end` завершает текущую страницу после иллюстрации, `embedded-caption` скрывает дублирующую подпись, уже присутствующую в скане.

Развороты выравниваются по физической чётности печатных номеров: чётная страница находится слева, нечётная — справа. Одиночные краевые страницы не порождают пустых DOM-страниц. Первая часть составной схемы может делить страницу с текстом; вторая начинается на следующей нечётной странице. Внутренние отступы на стыке убираются, изображения сохраняют одинаковые масштаб и вертикальную позицию.

Пагинированные страницы не содержат добавленных колонтитулов: остаётся только номер на внешнем нижнем крае. Сканированные изображения показываются без затемнения и цветовых фильтров. Области вырезаются из качественного PDF с небольшим запасом исходной бумаги вокруг содержимого; у двух частей принципиальной схемы итоговая высота кадров одинакова. Мобильный непрерывный reader по ADR-0008 не использует эти разрывы и специальные сетки.

## Альтернативы

- **Одинаковые двухколоночные страницы для всех материалов.** Проще сопровождать, но заметно искажается оригинальная композиция и число страниц.
- **Публикация целых страниц как изображений.** Точнее визуально, но теряются выбор текста, доступность, адаптивность и семантическая разметка.
- **Сырый HTML в Markdown.** Позволяет произвольную вёрстку, но смешивает содержание с представлением и отключён в renderer.

## Последствия

- (+) Число страниц, разворот и расположение основных иллюстраций соответствуют источнику.
- (+) Текст остаётся семантическим и доступным, а мобильный режим не усложняется.
- (+) Не появляются искусственные пустые страницы для выравнивания разворотов.
- (−) Специализированная сетка требует отдельных E2E-проверок и ручной сверки при изменении содержимого.
